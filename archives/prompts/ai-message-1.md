表記と構文

区切り文字: ご指定の HIT-C10/SPRT は、草稿の構文では / がM属性内の区切りです。そのため SPRT がM属性の一部と解釈されてしまいます。本文書の表記は HIT-C10-SPRT としました。スラッシュ区切りを正とする場合は、構文の定義側を変更します。
小文字の c との矛盾: 「フラグは大文字で記載する」という規則と、小文字の c が矛盾していました。そこで、大文字と小文字を区別する規則に改めました。あわせて、国際化プロファイルでは C と c に別の文字を割り当てることを必須としました。
H と N の整理: 草稿の例 HIT-N-SP は、M属性に N を置いていました。M属性の「人間作成」を H、T属性の「情報なし」を N に統一し、この例は HIT-C10-SP に直しました。途中で切れていた「M属性がHの場合」の規定も補完しています。

IPTCとの対応

用語名を正式な compositeWithTrainedAlgorithmicMedia に修正しました。
c は trainedAlgorithmicMedia に対応させました。
H は digitalCreation に対応させました。humanEdits は「非生成的ツールによる人間の編集」を指す用語で、人間による作成そのものには digitalCreation のほうが適合するためです。

Sフラグの範囲

claude.ai のようなサービスでは、運営者が設定したシステムプロンプトを申告者が入手・添付できない場合があります。そのため S を「申告者が設定または入手できたシステムプロンプト」と定義し、除外部分はその旨を併記する形にしました。
本文書自体の S と P の開示対象は、付録Aにプレースホルダーとして残しています。お手元のプロンプト等を添付してください。
